# D-0017 — Validate stance replay and aim pounces at the destination face

The independent-client wall-to-ceiling experiment reproduced a server correction:
the client reported feet at (15.1, 80, 8), including the half-body stance shift;
the server replayed that displacement and then applied the stance shift again.
Floor entry had hidden this because vanilla ignores the vertical discrepancy.

For an already bent wearer with the full set, `WallWalk.replayMove` considers the
inverse into-wall shift only when the reported old-up displacement warrants it.
Each candidate runs the existing collision calculation without moving the player
or triggering block effects. A bounded inward probe confirms the actual stopping
face. `Transition.intoWall` must reproduce **all three reported coordinates** to
within 1e-5 and produce a collision-free box. Only then does the normal server move
use that candidate, followed by the existing rule once. Otherwise it receives the
original displacement. Vanilla speed, penetration and movement-error validation
remain in place. No new packet or client-authority exception is introduced.

Real-server regressions cover all four walls entering the ceiling, forged endpoints
inside the ceiling and an undressed player. Knockback compares the actual vanilla
operation across six gravity frames, grounded/airborne state, initial velocities,
strengths and resistance values. Degenerate direction randomization is not compared
sample-for-sample; the test directions have a nonzero local horizontal component.

The six-surface pounce test found a second defect: a floor launch aimed above a
ceiling using its own up and landed four blocks short. The pounce now resolves the
immediate support at its destination with the existing cell casts and uses that
face's clearance offset. Targets with no nearby support retain the previous fallback.
This is one bounded query per pounce; world gravity, speed and flight integration
are unchanged. Real creature tests cover floor, ceiling and all four walls, including
airborne flight, the landing normal, reach and a free collision box.

## Independent clients

The test uses a dedicated server bound to loopback and two separate Minecraft JVMs
with ordinary TCP logins. The wearer finishes joining, then sets Minecraft's built-in
`noRender` flag and hides its window. Its input, physics and networking continue.
Only then is the rendering observer launched. Both must report ready before fixture
teleports begin. The observer uses the actual entity/equipment/frame packets and
its actual RemotePlayer interpolation target for motion packets. Fixture orchestration
uses normal system/chat messages; no shared Minecraft object or FakePlayer supplies
observed state.

`devtools/multiplayer.py` owns the process groups, enforces startup ordering and
cleanup, and requires complete server/client markers with zero movement corrections.
Its world is disposable and recreated: reusing a dead test player's save caused a
startup failure. Fixture teleports reset accumulated fall state. Lights make the
observer's shaded armour and orientation reviewable. The fixture never changes a
live server or the user's Prism instance.

New pounce arenas have declared bounds large enough for every block they place.
Pounce and minded hearing test creatures are explicitly persistent: distant players
left by other tests otherwise triggered vanilla despawning before their first tick
(observed tickCount zero, RemovalReason.DISCARDED, chunk entity-ticking true).
This affects fixtures only, not natural-spawn persistence.

Creature listening suitability still requires Rusty's judgment; no signal metric
or silent booth establishes it. Release authorization is separate from these checks.

The fixture resets the connection's saved movement origin after its explicit teleports
between opposite walls, so those setup jumps are not mistaken for player movement.
The final driver completes all three process gates with no speed or position corrections;
the normal full shader booth separately passes all 44 assertions. Full headless results
are 123 JUnit and 32 actual server tests. Test-only classes are absent from the held jar.


### Release-booth sampling correction (2026-09-16)

A clean release build failed the older integrated-booth movement comparison for one
tick, with no vanilla movement rejection. An unchanged diagnostic rerun passed. The
comparison queued server work that then read the live client entity on another thread,
so it could compare different movement instants. The booth now sends sixty immutable
position samples after the corresponding normal movement packets on the same connection.
NeoForge dispatches the sample handlers on the server main thread; atomic counters
report the verdict back to the integrated booth. Completion requires all sixty samples
and zero discrepancies. The Gradle gate additionally rejects vanilla moved-wrongly or
moved-too-quickly warnings. These changes affect test code only; production movement
and the independent two-client checks are unchanged.
