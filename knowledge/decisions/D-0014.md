# D-0014 -- The server judges a wearer's frame inside its re-run of each reported move, never by teleport

**Decision**: the wall-walk's transition rule runs on the server right after the server
re-runs a move the client reported and before the server compares its position with the
client's (`ServerGamePacketListenerImplMixin` on `handleMovePlayer`), as well as after the
server's tick for what no move decides (the set coming off, water). A take sets the position
on both sides and never sends a teleport. D-0009's "the client runs the same rule a tick
ahead and the two agree" stands; this is where the server's half of it has to run.

**Why**: Rusty: "The gravity system for the chitin armor is totally fucked." Reproduced by
putting the booth's wall-walk player in survival: the client's take moves its feet onto the
wall's face and it reports that position; the server's re-run of the same move had not yet
taken the wall (the rule ran at the end of the server's tick), so the positions differed by
the take, the server logged "moved wrongly" and teleported the client back, and from then on
the client's frame stayed on the wall -- the server's frame byte never changed, so nothing
overwrote the client's prediction -- while the server re-ran every move in the world's frame
on the ground: half a block climbed in sixty ticks, the box wrong, the view rolled. The
server-side teleport in a take would have hurt too: it drops the client's next moves until
the client answers it. The booth's player was in creative, which skips the "moved wrongly"
check, so the booth's wall scene had passed since 1.0.0.

**Rejected**: sending the frame in a packet from the client (the server would take the
client's word for which way is down); widening the server's tolerance (a hack around the
check, and the take is a whole box's turn, not a rounding); keeping the take's teleport (it
is the client's own position already, and the teleport window drops moves).

**Consequences**: the booth's wall scene is in survival and counts the ticks the server's
position is over half a block from the client's, and checks the server's own frame; a
wearer on a dedicated server with latency is covered by the same rule, since the server
judges each move as it arrives. The remaining phase-C items (placement facing, shadow and
nameplate, explosions in the frame, the back camera) are unchanged.
