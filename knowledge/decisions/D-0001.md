# D-0001 -- A creature is a profile and one entity type; its mind will be a tree

**Decision**: a creature is an entry of the datapack registry `aberrantmobs:creature`
(`CreatureProfile`, a `RecordCodecBuilder` codec with every bound checked in the compact
constructor) naming a Blockbench project, and every creature is the one entity type
`aberrantmobs:aberrant`, its profile id in synced data, looked up in the registry on every
read so a reload is honoured. In the phases to come the profile carries the rig's names,
the stats, the habitat, the loot, the sounds, and the mind as a decision tree of conditions
over named senses and verbs the protocol implements in Java; a new creature with existing
verbs is data only.

**Why**: Rusty: "I will be adding more monsters ... perhaps a protocol"; "the various
mobs we create should have decision trees to help dynamically govern their behavior";
chosen over Java per mob with a shared toolkit. Vanilla Wheels proved the shape (one
entity, a profile, a datapack registry, data-only consumers).

**Alternatives rejected**: *an entity type per creature* -- puts what a pack could say
into Java and needs a registration per mob; *an item data map* -- creatures are not items.
