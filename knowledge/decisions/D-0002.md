# D-0002 -- The rig keeps the project's bones; animation is ours, the file untouched

**Decision**: the friend's `.bbmodel` ships as saved and is read by `domain/BbRig` into a
`Rig`: every group a `Bone` with its origin and rotation, every cube on its group's bone
relative to the bone's pivot, cube rotations baked, group rotations applied at placement
(`W(b) = W(parent) * T(pivot_b - pivot_parent) * R(rest_b) * R(pose_b)`), a synthetic root
bone 0 at the origin. A `Pose` turns bones about their pivots or places them outright.
The file has no animations and none are asked of the friend: the walk (planted feet, a
trail-following chain, an undulation) and the attacks (authored clips) are code in the
domain, tested, in the next phases.

**Why**: Vanilla Wheels' `BbModel` flattens the outliner and discards pivots, which a
still vehicle never needed; a creature is posed. The reader is proved against the saved
file itself (the world bounds and a twice-turned leg's corner match an independent Python
reading), so the rest pose is Blockbench's, not an approximation. Rusty: "animations, can
you create those?" -- yes, procedurally and as clips, without touching the model
(`working-with-rusty`: a collaborator's file is used as received).

**Alternatives rejected**: *a Blockbench animation export* -- nothing to export;
*per-cube bones* -- 288 matrices a frame for no gain now; a cube can be promoted to a
child bone later without changing `Pose`'s type.
